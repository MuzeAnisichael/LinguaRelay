# v0.1.5 第一版全面优化设计

## 目标

v0.1.5 不以替换整个识别引擎为前提，先修正最影响体验的四个系统问题：增长音频窗口被过度重复推理、长字幕堆积、关键功能入口过深，以及首次安装缺少硬件分档。实时链路继续保证“大模型失败不影响本地字幕”。

## 实时字幕策略

```text
320 ms 音频块
  -> 能量门控和有界音频队列
  -> 320/640/960 ms 自适应 partial 调度
  -> 连续假设稳定前缀
  -> 标点 / 短停顿 / 6 秒硬上限断句
  -> 本地 M2M100 快译
  -> 同一 segment/revision 原位更新悬浮窗
  -> final 可选异步 LLM 修正
```

- 前 1.6 秒保持 320 ms 调度，尽快出现首批识别结果。
- 1.6–3.2 秒改为至少 640 ms，3.2 秒后改为至少 960 ms，降低 Whisper 对增长窗口反复推理的成本。
- 默认 3.2 秒后遇到短停顿即可切段；稳定句号、问号、感叹号、分号可以提前结束；连续语音最长默认 6 秒。
- 推理、翻译和 UI 都比较 segment/revision，过期译文不能覆盖较新的识别结果。
- “识别上下文”作为显式固定语言的初始提示和热词，适合填写会议主题、人名、公司/产品和专业术语。

设置页提供三种起点：平衡（默认）、极速字幕和省资源。它们是参数模板，不隐藏用户的自定义能力。

## 大模型修正

大模型页统一管理修正方式、服务类型、API 地址、模型 ID、密钥环境变量、前文条数、超时、速率、最大 Token 和温度。提供 Ollama、LM Studio 本地端点预设，但不捆绑或静默下载任何 LLM。

- `off`：完全不调用大模型。
- `asynchronous`：只在完整句快译显示后异步修正，是推荐模式。
- `live`：partial 与 final 都可提交，适合高性能本地服务，但消耗和结果抖动更大。
- 本地端点只允许回环地址；云端端点必须使用 HTTPS。
- 密钥继续只从环境变量读取，不进入 TOML、日志和字幕历史。
- provider 超时、限流、断开或熔断时，本地 ASR/MT 继续工作。

## 悬浮窗交互

顶栏保留简短状态，在右侧加入五个 24–26 px 控件：暂停/继续、仅译文/双语切换、历史、设置和隐藏。点击穿透模式会隐藏按钮，避免展示不可用控件；托盘和全局快捷键仍然是恢复入口。拖动、边缘/四角缩放、保留时间和字体配色保持兼容。

## 模型安装

首次启动先验证现有模型，再展示两个固定版本的可复现方案：

- 均衡 Small（推荐）：约 1.36 GiB，优先质量，适合 16 GB 内存或 NVIDIA GPU。
- 轻量 Base：约 1.05 GiB，优先速度和占用，适合 8 GB 内存或低功耗 CPU。

用户还可以验证已有目录或从离线 ZIP 安装。每个包都有独立 GitHub Release URL、最大尺寸、完整文件列表、SHA-256、上游版本和许可证。选择结果写入本地配置，使实际加载模型与已验证清单一致。

## 验收标准

- 所有 12 个中/日/英/韩方向仍可选择，禁止自动语言检测回退。
- 长语音 partial 调度不会持续保持 320 ms；默认单段不超过 6 秒。
- 旧 translation revision 不覆盖更新的 transcript revision。
- 大模型关闭或故障时，本地快速字幕不受影响。
- Small/Base 两套模型包均能由内置清单组装并逐文件验证。
- 悬浮窗快捷按钮、点击穿透、拖动缩放和设置持久化通过 Qt 无界面测试。
- Python 测试、Ruff、PyInstaller、Inno Setup、发布资产校验全部通过后才创建 `v0.1.5` 标签。

## 下一阶段

这一版仍基于 Whisper 滑动窗口，无法完全消除重复计算。后续应 A/B 测试真正有状态的流式 ASR、神经前置 VAD、双阶段快速/精确识别，以及按麦克风和系统输出分轨的会议模式；是否替换模型要由中、日、英、韩共同基准决定。
