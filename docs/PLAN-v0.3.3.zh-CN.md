### 已确认的过载交互

- 正常工况保留完整句（final），过期中间识别（partial）允许替换；不能静默丢 final 来换取低延迟。
- 达到容量/等待截止时，受影响工作必须有明确的待处理、失败或取消归宿及计数，用户看到“字幕处理过载/暂停”等状态；不无限积压或伪装成功。
- **持续过载策略：暂停受影响的实时字幕分支并告警，录制继续；恢复时隔离旧代结果。** 已接收 final 在正常/短暂拥塞时保留，持续过载下未接收或中止的片段明确统计；不宣称所有工作在任意负载下都能完成。
- 优先保护录制继续消费；仍不额外保存默认实时音频。用户没有开始录制的内容，不承诺事后能恢复音频或补译。
- 停止先解除队列等待与数据流互等；正在执行的原生调用仍可能延后结束，必须诚实报告，不直接杀线程或提早宣告资源释放。
- 停止各阶段共用同一总截止时间，不能串行累加独立超时；到期报告未完成任务、隔离晚结果，保留仍被原生调用占用的资源，不假报已完全停止。具体预算与容差用故障夹具核定。

自动把积压音频落盘并稍后补译是另一种产品策略，会改变默认实时不留存音频的边界，需独立授权与设计；不是本轮的默认方案。暂停/恢复是告警后的明确状态，不自动复用仍被旧推理调用占用的模型。

本轮已用受控满队列夹具复现旧等待环；实现采用非阻塞 admission、1 秒输出/服务等待、四块音频 handoff 与共同停止期限。回归及两个新回放详见[当前验证](VERIFICATION.zh-CN.md#2026-10-06-当前源码验收)。已有模型回放是新配置基线，没有与修改前同配置对照，不能声称实测提升。

## 验证顺序与交付条件

1. **基线**：在修改应用代码前记录当前源码回归与可运行的同配置回放；先补可重现失败场景，不使用无限挂起的测试。
2. **定向回归**：队列/ASR/MT/service/音频运行时的满 final、慢消费者、停止、恢复、录制样本守恒；检查 final 归宿、乱序/重复与旧 revision 覆盖。
3. **观测与报告**：固定单调时钟关联，结果缺失和失败样本纳入统计；界面接收、更新确认和实际绘制按证据分开。共享 CI 不设置不可靠的亚秒级速度硬门槛。
4. **非付费对照**：仅使用已有本地权重和公开/获授权语料，固定机器、模型文件/精度/beam/分段参数、输入顺序，分冷启动/热态进行前后对照。小型四语/12 路由样本只证明回归，不证明所有内容质量合格。
5. **完整源码检查**：Ruff、格式、pytest、应用依赖环境校验、文档/ID/链接检查。前轮开发环境已有无关依赖冲突时，使用可核验的项目隔离环境，报告差异，不能顺手卸载其他项目依赖。
6. **GitHub**：本地验收通过后提交并推送本任务相关源码与文档，核对对应提交的 CI；CI 失败须继续处理，不能只交付“已推送”。

缺模型/合法语料时不自动下载，单独标记模型实测未执行；没有设备长测或母语人工评审时继续保留相应问题。K-001 按实际修复/验证范围更新，真实设备残余验收不伪造；K-002/K-003 只能部分完成，不能因工具存在而全部关闭。

## 当次授权与非目标

- 用户已要求开发和测试后推送 GitHub；本计划默认 **源码提交/推送**，不是自动打标签、构建/安装 EXE、上传 GitHub Release。
- 不调用付费 API；测试 LLM 故障使用假 provider，不读取或上传私人字幕。历史 OpenRouter $1 预算不复用。
- 不自动下载模型，不改变用户现有模型/语言配置，不覆盖原始媒体，不测试生产安装卸载。
- 不增加语言、自动检测、混音、跨平台、LLM SSE、新识别模型、批量任务、断点续跑或签名；它们见[后续版本路线](ROADMAP.zh-CN.md#后续版本规划2026-10-06-草案)。
- 若用户本次希望同时发布安装版/便携版，需要明确纳入发行验收；包体、版本一致性、冻结 EXE、自测、隔离安装与干净机器边界不能由源码 CI 代替。
- 当日 `gh auth status` 报告原账户 token 失效；公共 API release 查询成功，Git 的推送认证需实际核验。不读取/修改凭据，不把公共查询失败与 CLI 登录混写；实际交付结果以交接记录为准。

当前状态和下一步以[交接记录](HANDOFF.zh-CN.md)为准。同一已确认范围内继续实施；扩大付费、留存或发行范围需另行确认。
