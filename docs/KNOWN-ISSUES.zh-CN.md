## 登记规则

- `K-xxx` 是待处理问题、风险或验证缺口；`H-xxx` 保留历史修复。编号不重用；问题关闭后保留证据，不删除旧记录。新增证据应注明日期、提交、数据、硬件和配置，不覆盖原始基准。
- 优先级是建议的排查顺序：**P1** 影响核心链路、数据可靠性或验收可信度；**P2** 质量、性能或场景边界；**P3** 后续能力与用户暂缓事项。它们不自动授权代码修改。
- 状态区分“待复现风险”“验证缺口”“待设计”“部分缓解”“已修复（注明范围）”“用户暂缓”。静态分析不能写成现场复现；逻辑测试不能写成真实设备性能结论。
- 证据强度：**E1** 源码或历史变更可定位；**E2** 有对应的可重放回归用例，是否通过仍须关联实际执行记录；**E3** 有指定环境/数据的历史实测。E3 也不是全场景认证，缺失证据应明确写出。
- 所有条目于本页登记日期回填；各条目中的历史证据保留原日期。未来更新只修改相关条目及索引，并记录新证据。修改门槛、模型、默认行为或云端数据范围前，须先确认需求；付费调用、用户音频和发布须另获授权。

## K-001

**满 final 队列可能相互等待，并拖住同线程录音消费**

- **优先级／状态／证据：** P1；受控路径已复现并修复，真实设备残余验证未关闭；E2 新故障回归。不宣称曾发生用户现场死锁或实际录音丢失。
- **相关需求：** R-LIVE-01、R-AUDIO-01、R-REC-01、R-QUALITY-01。
- **影响与现状：** 用 `git show af920a5` 的原始队列/MT 源码在内存夹具中复现容量 2 的 final 输入/输出同时满、双方等待；主动关闭后退出，没有遗留线程。新版 admission 默认非阻塞、输出最多等 1 秒，服务下游优先抽取并有限重试；音频录制消费与实时提交分线程。持续过载显式暂停/取消字幕工作、录制继续；原生/磁盘调用不能硬杀，超时保留所有权并拒绝提前释放/重启。
- **当前位置：** [队列](../src/lingua_relay/asr/buffer.py) `put_final` / `LatestEventBuffer.put`；[ASR](../src/lingua_relay/asr/streaming.py) `_submit` / `stop`；[MT](../src/lingua_relay/mt/streaming.py)；[服务](../src/lingua_relay/service.py) `_pump_asr` / `_shutdown_workers`；[音频运行时](../src/lingua_relay/audio/runtime.py) `_run`。
- **当前回归：** [生命周期故障](../tests/test_streaming_lifecycle.py)、[服务背压](../tests/test_service_backpressure.py)、[录制隔离](../tests/test_audio_runtime.py)、[UI 迟到投递](../tests/test_desktop_delivery.py)。有截止时间的受控阻塞、final 保留/取消计数、关闭唤醒、共同停止预算、旧调用/显示隔离和合成录音样本守恒；执行结果见[验证索引](VERIFICATION.zh-CN.md)。
- **实现取舍：** [ADR 0003](decisions/0003-bounded-waits-and-recording-isolation.md)。重试拒绝次数不等于唯一丢句数；在途取消在原生返回后入账，返回前根据 worker_alive 显示未完成。无主动录制时不额外落盘音频。磁盘、设备缺样本与真实长测继续开放。
- **关闭条件：** 已复现的等待路径得到修复，或以证据明确排除静态假设；满 final、停止、慢消费者回归在指定截止内结束；录音连续性和过载恢复有对应环境证据。生命周期解耦的历史修复见 [H-002](#h-002)，不能据此关闭本项。

## K-002

**缺少当前真实音频到可见字幕的完整测量**

- **优先级／状态／证据：** P1；验证缺口；E3 历史阶段基准存在，但不能证明当前真实采集到 UI 的端到端目标。
- **相关需求：** R-LIVE-01、R-UI-01、R-LLM-01、R-QUALITY-01。
- **影响与现状：** M5 的“end_to_end”是历史 ASR 时间与另测 MT 推理时间的组合；OpenRouter 记录的是完整 API 调用，不含运行时排队与上屏。不能将阶段 P50 相加当作真实管线 P50，也不能用 API 两秒内完成率代替修正上屏率。
- **当前位置：** [M5 聚合脚本](../scripts/run_m5_quality_gate.py) `_measure_end_to_end`；[历史 M5](benchmarks/m5-release-gate.json)；[LLM 报告](benchmarks/OPENROUTER-v0.3.3.zh-CN.md)；[服务](../src/lingua_relay/service.py)；[悬浮窗](../src/lingua_relay/ui/overlay.py)。
- **复现／验证计划：** 使用公开或经同意的可复现音频，关联采集时钟、ASR/MT/LLM 排队、首次可用译文、稳定译文和实际 UI 显示；区分冷启动、热启动、持续语音、过载及空结果，记录 P50/P95、覆盖率与样本数。
- **候选办法：** 增加贯穿同一片段的时间戳和 UI 确认点，再比较现状与优化候选；指标定义和目标先获确认。
- **2026-10-06 部分完成：** [有界追踪器](../src/lingua_relay/telemetry.py)、[合成回放](../scripts/run_reliability_replay.py)、[本地模型回放](../scripts/run_local_pipeline_replay.py) 已加入；关联同一 segment/revision，分别记录识别预览、译文 widget 更新、缺失/失败/取消与采样 RSS。不含真实 WASAPI、物理绘制或完整 LLM 阶段，不关闭本项。
- **关闭条件：** 指定提交、硬件、音源、语言方向的端到端报告可复现，明确未达标和未覆盖项；不能以单元测试或历史报告关闭。

## K-003

**历史 M5 门槛不足以证明高质量，人工和方向覆盖仍不足**

- **优先级／状态／证据：** P1；验证缺口；E1 门禁逻辑与 E3 历史报告直接可查。
- **相关需求：** R-QUALITY-01、R-LANG-01、R-LLM-01。
- **影响与现状：** M5 的 ASR 门槛允许错误率不超过 100%，MT 虽记录质量分数，却未设置相应质量通过阈值；`all_passed` 不能作为高准确率证明。12 路由有小型烟雾基准，不等于每个方向有充分口语、领域和母语人工验收。OpenRouter 定向合成样本的模型辅助盲评不等于人工专家评估。
- **当前位置：** [门禁脚本](../scripts/run_m5_quality_gate.py) `gates`；[M5 报告](benchmarks/m5-release-gate.json)；[基准索引](benchmarks/README.md)；[LLM 质量边界](benchmarks/OPENROUTER-v0.3.3.zh-CN.md)。
- **复现／验证计划：** 审计每个门禁实际覆盖的指标；建立固定留出集，分语言/方向/噪声条件报告 WER/CER、语义错误、数字/否定/术语、断句与误改，并记录人工审阅方式。仅按参考译文字面匹配不能判定语义正确。
- **候选办法：** 分离可运行性、性能和质量门禁；先约定方向级阈值及严重错误规则，再扩充语料和人工评审，不为通过而调松阈值。
- **2026-10-06 部分完成：** 新 [门禁评估器](../src/lingua_relay/telemetry.py) 独立报告功能/性能/质量的 pass、fail、not_evaluated，拒绝空数据、无效数值、重复项和混配置。旧 M5 脚本/JSON 保留历史口径，不再用于新版本高质量结论；方向级阈值、充分语料与人工质量仍未完成。
- **关闭条件：** 新门槛和评审方式经确认，报告同时覆盖接受项与失败项，未验证方向明确标注；保留旧报告及其宽松条件，不回写历史结果。

## K-004

**Whisper 重叠窗口仍有重复计算，过期推理统计不完整**

- **优先级／状态／证据：** P2；部分缓解；E1 源码，E2 调度/缓冲回归，E3 指定配置的历史基准。
- **相关需求：** R-LIVE-01、R-MODEL-01、R-QUALITY-01。
- **影响与现状：** 已有 320/640/960 ms 自适应调度、partial 替换和有界队列，但仍重算窗口。0.3.3 本轮补齐 `_stale_results_dropped`：统计 abort 后完成而被屏蔽的推理结果；保留已经开始、随后被更新 partial 排队时仍能显示的原体验。该计数为零不表示没有重复或过期计算，排队替换、取消/输出拒绝、显示抑制另计；LLM 仍是独立计数。
- **当前位置：** [ASR 流式实现](../src/lingua_relay/asr/streaming.py)；[MT 流式实现](../src/lingua_relay/mt/streaming.py)；[调度回归](../tests/test_asr_streaming.py)；[历史优化方案](OPTIMIZATION-v0.1.5.zh-CN.md)。
- **复现／验证计划：** 用慢推理夹具区分“排队前替换”“开始前已过期”“完成后不可显示”，核对计数与实际调用；真实负载另测 RTF、队列年龄、CPU/GPU、内存和首条字幕延迟。
- **候选办法：** 基于排队年龄的自适应调度、开始前淘汰过期 partial、统一计数定义；有状态流式 ASR 作为独立对照，需验证四语覆盖、质量和硬件成本。
- **关闭条件：** 指标可由受控测试校验，统计不再误导；获准优化后用同数据/硬件证明收益，并保留 final 与停止回归。

## K-005

**六秒硬切与在线语音门控仍存在跨段和起音边界风险**

- **优先级／状态／证据：** P2；待验证／待设计；E1 规则可定位，具体漏词、重复率与误切率尚缺当前场景实测。
- **相关需求：** R-LIVE-01、R-LANG-01、R-QUALITY-01。
- **影响与现状：** 标点、短停顿和默认六秒上限已经缓解字幕堆积，但硬切不保证语义完整。新片段重新建立 ASR 状态，固定提示/热词不是动态跨段语境；在线能量门控与 final Silero VAD 也不等于前置神经 VAD。轻声起音、尾音、长句跨切点需单独验证。
- **当前位置：** [分段器与稳定前缀](../src/lingua_relay/asr/streaming.py)；[Whisper 调用](../src/lingua_relay/asr/faster_whisper.py)；[配置](../src/lingua_relay/config.py)；[架构](ARCHITECTURE.md)。
- **复现／验证计划：** 使用恰好跨切点的数字、否定、专名及中日韩句末谓语，加入轻声开头、短停顿和音乐；按音频对齐统计漏词、重复、错分段和延迟，而不是只看文本长度。
- **候选办法：** 有上限的动态前文、切点音频重叠与去重、前置 VAD 配合预留起音、语义端点；新增等待和跨段提示可能增加延迟或传播错误，需对照。
- **关闭条件：** 分段边界数据集和指标明确；候选若获批准实施，须同时满足约定延迟与边界准确性，不能只延长窗口。

## K-006

**稳定译文和翻译上下文尚无完整策略**

- **优先级／状态／证据：** P1；待设计；E1 当前调用和上下文路径，实际回改程度待测。
- **相关需求：** R-LIVE-01、R-LLM-01、R-UI-01。
- **影响与现状：** MT 对整个 `event.text` 重译，缓存按整串文本命中，目标前缀只有语言标记；没有持久的已确认译文前缀或跨片段 MT 上下文。实时 LLM 的历史来自提交时的 final 快译，成功修订未回写该上下文。只冻结已显示前缀也可能把早期误译锁死，不能直接宣称更准确。
- **当前位置：** [MT 调度](../src/lingua_relay/mt/streaming.py)；[M2M100 解码](../src/lingua_relay/mt/m2m100.py)；[修正上下文](../src/lingua_relay/correction/engine.py)；[修正提示词](../src/lingua_relay/correction/prompt.py)。
- **复现／验证计划：** 回放逐步增长和回改的 ASR 假设，覆盖否定词晚到、主谓语序变化、代词和跨段术语；测回改字符数、误锁前缀、首条可用译文与最终语义质量。
- **候选办法：** 稳定前缀与可变尾部分离、软偏置/有限回改、按来源记录短上下文；不能把未经验证的 LLM 译文自动当作可信事实。更换同传模型另需数据、许可和硬件评估。
- **关闭条件：** 先确认临时/确认译文的交互契约，再以同输入对照证明可读性收益且无不可接受的语义回退。

## K-007

**新片段占位打断阅读，LLM 实际上屏覆盖率未知**

- **优先级／状态／证据：** P1；验证缺口／待设计；E1 显示条件，E2 旧修订保护回归；没有当前真实上屏率报告。
- **相关需求：** R-UI-01、R-LIVE-01、R-LLM-01、R-QUALITY-01。
- **影响与现状：** 新 ASR 片段立即把译文改成“正在翻译…”。修正仅在当前 segment 且父 revision 不落后于当前来源 revision 时上屏，避免旧内容覆盖新内容；已切到下一片段的 final 修正在启用历史时可写入却不显示。API 成功率、修正生成率和用户实际看到的比例不同。
- **当前位置：** [悬浮窗](../src/lingua_relay/ui/overlay.py) `publish_transcript`；[服务](../src/lingua_relay/service.py) `_pump_revisions`；[修正历史](../src/lingua_relay/correction/engine.py)；[显示回归](../tests/test_service_correction.py)。
- **复现／验证计划：** 用可控快译/修正延迟与连续新片段记录每个版本是否上屏、驻留多久；覆盖仅译文/双语、保留时间、隐藏/恢复和无译文情况。
- **候选办法：** 保留上一条稳定译文，当前条使用独立临时区；限定最近片段修正窗口，超时结果仅入历史。窗口高度、回改提示与用户注意力成本须先确认。
- **关闭条件：** 上屏/历史/舍弃分别可计数；经确认的显示方案有可读性及端到端对照，不破坏旧结果不能覆盖新来源的保护。

## K-008

**LLM 非流式、吞吐上限与缺少声学证据的误改边界**

- **优先级／状态／证据：** P2；部分缓解；E1 当前实现，E2 故障回归，E3 2026-09-07 EN→ZH 定向文本实测。
- **相关需求：** R-LLM-01、R-LIVE-01、R-QUALITY-01、R-PRIVACY-01。
- **影响与现状：** 已有连接池、超时、熔断、取消及过期保护；API 为 `stream=False`、单工作线程，默认 30 RPM，队列满或限流会跳过修正。`live` 不等于逐 token 上屏。提示词只携带文本，无法可靠恢复 ASR 听错的音频事实；历史样例仍出现否定/位置遗漏、补全未说内容及误改正确译文。实时 final 仅启用历史时保留版本链；[离线处理器](../src/lingua_relay/offline/processor.py)只保存最终 cue，没有同等原译文/provider/版本追溯。
