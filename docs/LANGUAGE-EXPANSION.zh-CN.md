# 更多语言扩展方案

LinguaRelay v0.3.0 继续正式支持简体中文、日语、英语和韩语全部 12 个方向。后续扩展不应只把语言代码加入下拉框；每种新增语言都要同时通过识别、翻译、字体、断句、导出和人工质量门槛。

## 建议分阶段

### v0.4：第一扩展组

优先评估西班牙语、法语、德语、葡萄牙语、俄语和意大利语。这些语言拥有较丰富的公开语音与翻译评测集，Whisper 覆盖成熟，桌面字体与标点处理复杂度相对可控。

### v0.5：东南亚与南亚组

评估泰语、越南语、印度尼西亚语、印地语。需要额外解决无空格断句、组合字符、字体回退、数字格式和低资源方向翻译质量。

### 后续：阿拉伯语等双向文字与低资源语言

先完成 Qt 双向文字、字幕导出、标点方向和混合拉丁字符的专项测试，再开放为稳定选项。

## 技术路径

1. 将语言目录扩展为能力清单：分别声明 ASR、实时 MT、离线 MT、LLM 精修、字体与断句规则，而不是假设每个 provider 支持相同语言。
2. ASR 继续以多语言 Whisper / faster-whisper 为基线，显式传入语言；针对低资源语言比较 Large-v3 Turbo、Large-v3 和可替换 ASR provider。
3. M2M100 可作为广覆盖实验基线，但每条语言方向都必须单独验收。若某些方向不达标，优先增加明确标注的直译模型或用户选择的 API，不静默经英语枢轴翻译。
4. NLLB-200 只用于研究比较：其常见 distilled 600M 检查点采用 CC-BY-NC-4.0，不适合作为本 MIT 项目可自由再分发的默认商用模型包。
5. 把标点、字符长度、空格规则、字体回退和规范化从全局判断拆成按语言策略；WebVTT/SRT/ASS 都要验证 Unicode 与双向文本。
6. 本地模型安装器按语言包或 provider 显示下载量、许可证、硬件需求和覆盖方向，避免为了少数语言强制所有用户下载巨型模型。

## 上线门槛

每种语言至少需要：

- 合法且固定版本的公开语音集（例如 FLEURS）与平行文本集（例如 FLORES）；
- 安静语音、会议、媒体背景、口音和专有名词样本；
- WER/CER、首条字幕延迟、翻译质量、术语命中和人工可读性评分；
- 与至少两种目标语言的直接双向测试，而不是只测到英语；
- CPU 与 NVIDIA GPU 的资源上限；
- 母语审阅者确认断句、标点、字体和字幕导出。

在达到这些门槛前，新增语言应标记为“实验性”，且不能降低四种现有语言的实时延迟与稳定性。
